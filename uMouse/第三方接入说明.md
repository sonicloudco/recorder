---

## 一、产品概述

本 SDK 用于与「声云智能鼠标」硬件设备通信，封装了 **USB（HID）** 与 **BLE（蓝牙低功耗）** 两种连接方式下的设备发现、协议解析与音频解码能力，对外输出三类数据：

1. **原始按键事件** —— 哪个键 + 什么动作（按下/抬起/长按/单击），**不做任何业务映射**；
2. **离散事件** —— 设备信息（序列号/电量）、DPI 变更、会议状态等，以 JSON 字符串上报；
3. **PCM 音频流** —— 16 kHz / 16 bit / 单声道 / 小端的原始音频数据。

> **设计原则**：SDK 只负责「把硬件数据忠实搬运出来」，**所有业务逻辑由调用方自行实现**。例如 M 键按下后触发截图、语音转文字还是回车，由您的程序根据收到的 `keyEvent` 自行决定。这样 SDK 的对外接口可以长期保持稳定，硬件升级只需在 JSON 里新增字段。

### 平台支持矩阵

| 目标系统 | 架构 | 连接方式 | 对应交付包目录 |
|---|---|---|---|
| Windows | x64 | USB ✅ / BLE ✅ | `windows/` |
| 统信 UOS | x86 (amd64) | USB ✅ / BLE ✅ | `uosx86/` |
| 统信 UOS | ARM64 (aarch64) | USB ✅ / BLE ✅ | `UosArm64/` |
| 麒麟 Kylin | x86 (amd64) | USB ✅ / BLE ✅ | `kylinx86/` |
| 麒麟 Kylin | ARM64 (aarch64) | USB ✅ / BLE ✅ | `KylinArm64/` |
| 通用 Linux | x86 (amd64) | USB ✅ / BLE ✅ | `fdx86/` |
| macOS | x86_64 / Apple Silicon | USB ✅ / BLE ✅ | `MacOS/` |

> **重要**：各平台的动态库是**针对该平台编译**的，二进制不互通。请按您最终部署的目标系统选择对应目录下的包。UOS 与麒麟之间虽同为 Linux/glibc，但由于系统库版本差异，建议仍各自使用对应包。

```
├── include/
│   └── umouse_sdk.h

```

```
├── include/
```

## 三、快速开始（5 分钟跑通）

最快的验证方式：拿到包后，先运行自带的 demo，确认硬件连接与数据通路正常。

### 3.1 Windows

```bat
REM 直接运行（dll 已在同目录，无需额外配置）
windows\SDK\bin\umouse_demo.exe
```

### 3.2 Linux / 国产化系统

```bash
# USB 方式需要先安装设备访问权限（仅需一次，见「平台注意事项」）
cd <平台目录>/SDK/lib
./umouse_demo
```

运行后应打印：
```
uMouseSdk demo, version 0.1.0
[connected] <设备id> via USB
[message] <设备id> {"type":"deviceInfo", ...}
[audio len=] 320
running... 按回车结束。
```

按回车退出。期间收到的音频会写入 `out.pcm`（16 kHz / 16 bit / 单声道），可用 [Audacity](https://www.audacityteam.org/)「导入原始数据」播放验证。

## 四、集成到您的工程

本 SDK 为**纯 C ABI**，可被几乎所有主流语言直接调用。下面给出四种常见语言的集成示例。核心调用顺序都是：

> **注册回调 → `um_sdk_init()` → （SDK 内部自动探测设备并回调）→ 业务处理 → `um_sdk_close()`**

> ⚠️ 回调**必须在 `um_sdk_init()` 之前注册**，否则可能错过设备连接等早期事件。

### 4.1 C / C++

**编译/链接方式：**

- 头文件：将 `include/` 加入头文件搜索路径
- Windows（MSVC）：链接 `lib/uMouseSdk.lib`，运行期把 `bin/*.dll` 放到可执行文件同目录（或加入 `PATH`）
- Linux：链接 `-luMouseSdk`（`-L<包>/lib`），并设置 `LD_LIBRARY_PATH` 或用 rpath `$ORIGIN`
- macOS：链接 `-luMouseSdk`，用 `@loader_path` 作为 rpath

**最小示例：**

```c
#include "umouse_sdk.h"
#include <stdio.h>

static void on_connected(const char* id, int mode) {
    printf("[连接] %s via %s\n", id, mode == UM_CONN_BLE ? "BLE" : "USB");
}
static void on_disconnected(const char* id, int mode) {
    printf("[断开] %s via %s\n", id, mode == UM_CONN_BLE ? "BLE" : "USB");
}
static void on_message(const char* id, const char* json) {
    printf("[事件] %s %s\n", id, json);
}
static void on_audio(const char* id, const unsigned char* pcm, int len) {
    /* pcm 仅在本回调期间有效，需要留存请立即 memcpy 拷走 */
    /* 此处示例：写入文件 */
}

int main(void) {
    /* 1. 注册回调（init 之前） */
    um_register_connected(on_connected);
    um_register_disconnected(on_disconnected);
    um_register_message(on_message);
    um_register_audio(on_audio);

    /* 2. 初始化（debug=1 打开内部日志，排查问题时用） */
    um_sdk_init(1);

    /* 3. 等待业务运行……这里用 getchar 模拟 */
    getchar();

    /* 4. 释放 */
    um_sdk_close();
    return 0;
}
```

CMake 工程示例（推荐，自动处理平台差异）：

```cmake
cmake_minimum_required(VERSION 3.16)
project(my_app C)

add_executable(my_app main.c)

# SDK 包根目录（指向 windows/SDK 或 uosx86/SDK 等）
set(UMSDK_DIR "<你的路径>/windows/SDK")

target_include_directories(my_app PRIVATE "${UMSDK_DIR}/include")
target_link_directories(my_app PRIVATE "${UMSDK_DIR}/lib")
target_link_libraries(my_app PRIVATE uMouseSdk)
```

### 4.2 C# (.NET)

通过 **P/Invoke** 调用，无需任何第三方库。

```csharp
using System;
using System.Runtime.InteropServices;
using System.Text;

internal static class UMouseSdk
{
    private const string DLL = "uMouseSdk";   // Windows; Linux 改为 "libuMouseSdk.so"，macOS ".dylib"

    public const int UM_CONN_USB = 0;
    public const int UM_CONN_BLE = 1;

    public delegate void OnConnected(IntPtr deviceId, int connMode);
    public delegate void OnDisconnected(IntPtr deviceId, int connMode);
    public delegate void OnMessage(IntPtr deviceId, IntPtr json);
    public delegate void OnAudio(IntPtr deviceId, IntPtr pcm, int len);

    [DllImport(DLL)] public static extern void um_sdk_init(int debug);
    [DllImport(DLL)] public static extern void um_sdk_close();
    [DllImport(DLL)] public static extern IntPtr um_sdk_version();

    [DllImport(DLL)] public static extern void um_register_connected(OnConnected cb);
    [DllImport(DLL)] public static extern void um_register_disconnected(OnDisconnected cb);
    [DllImport(DLL)] public static extern void um_register_message(OnMessage cb);
    [DllImport(DLL)] public static extern void um_register_audio(OnAudio cb);

    [DllImport(DLL)] public static extern int um_get_device_count();
    [DllImport(DLL)] public static extern IntPtr um_get_device_id(int index);
    [DllImport(DLL)] public static extern int um_set_dpi(IntPtr deviceId, int level);

    public static string PtrToStringUtf8(IntPtr p) =>
        p == IntPtr.Zero ? null : Marshal.PtrToStringUTF8(p);
}

class Program
{
    static void Main()
    {
        // 必须把回调委托存为字段，防止被 GC 回收导致崩溃
        UMouseSdk.um_register_connected((id, mode) =>
            Console.WriteLine($"[连接] {UMouseSdk.PtrToStringUtf8(id)} via {(mode == 1 ? "BLE" : "USB")}"));
        UMouseSdk.um_register_message((id, json) =>
            Console.WriteLine($"[事件] {UMouseSdk.PtrToStringUtf8(UMouseSdk.PtrToStringUtf8(id) is var _ ? id : id)} {UMouseSdk.PtrToStringUtf8(json)}"));
        UMouseSdk.um_register_audio((id, pcm, len) =>
        { /* 拷贝 pcm：Marshal.Copy(pcm, buffer, 0, len); */ });

        UMouseSdk.um_sdk_init(1);
        Console.WriteLine($"SDK 版本: {UMouseSdk.PtrToStringUtf8(UMouseSdk.um_sdk_version())}");
        Console.ReadLine();
        UMouseSdk.um_sdk_close();
    }
}
```

> **C# 关键提醒**：用于 P/Invoke 的委托实例**必须被持有**（存为字段或静态成员），否则 CLR 的 GC 会回收它，SDK 回调时将访问已释放的内存导致崩溃。

### 4.3 Python

使用标准库 `ctypes`，无需安装额外依赖。

```python
import ctypes
from ctypes import c_int, c_char_p, c_void_p, CFUNCTYPE

# Windows: uMouseSdk.dll;  Linux: libuMouseSdk.so;  macOS: libuMouseSdk.dylib
lib = ctypes.CDLL("./libuMouseSdk.so")   # 按你的平台改

# 定义回调函数签名
ON_CONNECTED = CFUNCTYPE(None, c_char_p, c_int)
ON_MESSAGE   = CFUNCTYPE(None, c_char_p, c_char_p)
ON_AUDIO     = CFUNCTYPE(None, c_char_p, c_void_p, c_int)

@ON_CONNECTED
def on_connected(device_id, mode):
    print(f"[连接] {device_id.decode()} via {'BLE' if mode else 'USB'}")

@ON_MESSAGE
def on_message(device_id, json):
    print(f"[事件] {device_id.decode()} {json.decode()}")

@ON_AUDIO
def on_audio(device_id, pcm, length):
    # pcm 是原始内存指针，立即拷出
    buf = ctypes.string_at(pcm, length)
    # ... 落盘 / 送识别

# 注册（init 之前）
lib.um_register_connected(on_connected)
lib.um_register_message(on_message)
lib.um_register_audio(on_audio)

lib.um_sdk_init(1)
print("SDK 版本:", lib.um_sdk_version().decode())

input("按回车退出...\n")
lib.um_sdk_close()
```

> **Python 关键提醒**：用 `@CFUNCTYPE` 装饰的回调对象必须**保持引用存活**（上面的写法作为模块级变量即可），不要写成临时变量传给 register。

### 4.4 Electron / Node.js

推荐使用 [koffi](https://github.com/Koromix/koffi)（活跃维护、支持回调）：

```js
const koffi = require('koffi');
const lib = koffi.load('./libuMouseSdk.so');   // 按平台改后缀

const um_sdk_init      = lib.func('void um_sdk_init(int debug)');
const um_sdk_close     = lib.func('void um_sdk_close()');
const um_sdk_version   = lib.func('const char* um_sdk_version()');
const um_register_msg  = lib.func('void um_register_message(void *cb)');

const OnMessage = koffi.proto('void OnMessage(const char* id, const char* json)');
// 回调必须用 koffi.register 注册并保持引用
const cb = koffi.register((id, json) => {
    console.log('[事件]', koffi.decode(id), JSON.parse(koffi.decode(json)));
}, koffi.pointer(OnMessage));

um_register_msg(cb);
um_sdk_init(1);
console.log('SDK 版本:', koffi.decode(um_sdk_version()));
```

## 五、API 参考

全部符号声明在 `umouse_sdk.h` 中，均为 `extern "C"`，符号统一前缀 `um_`。

### 5.1 生命周期

```c
void um_sdk_init(int debug);      // 初始化并启动内部设备探测线程与音频解码线程
void um_sdk_close(void);          // 停止并释放资源（幂等，可重复调用）
const char* um_sdk_version(void); // 返回版本号字符串，如 "0.1.0"
```

- `um_sdk_init` 内部会启动设备探测/读线程与音频解码线程。**注册回调应在调用之前完成**。
- `debug != 0` 时向标准输出打印内部日志，用于排查问题；生产环境建议传 `0`。
- `um_sdk_close` 是幂等的，程序退出前调用一次即可。

### 5.2 回调注册

```c
typedef void (*um_on_connected)   (const char* device_id, int conn_mode); // conn_mode: 0=USB 1=BLE
typedef void (*um_on_disconnected)(const char* device_id, int conn_mode);
typedef void (*um_on_message)     (const char* device_id, const char* json);  // UTF-8 JSON
typedef void (*um_on_audio)       (const char* device_id, const uint8_t* pcm, int len);

void um_register_connected(um_on_connected cb);
void um_register_disconnected(um_on_disconnected cb);
void um_register_message(um_on_message cb);
void um_register_audio(um_on_audio cb);
```

- 不需要的回调传 `NULL` 或不注册即可，SDK 不会因未注册而崩溃。
- `device_id`：设备唯一标识字符串（首版单设备，固定值）；指针仅在回调期间有效。
- `json`：UTF-8 字符串，**仅在回调期间有效**，需要留存请立即 `strdup` / 拷贝。
- `pcm`：音频数据指针，**仅在回调期间有效**，需要留存请立即 `memcpy`。

### 5.3 设备查询（同步）

```c
int         um_get_device_count(void);                  // 当前已连接设备数（首版 0 或 1）
const char* um_get_device_id(int index);                // 取第 index 个设备 id；越界返回 NULL
int         um_get_connection_mode(const char* id);     // 0=USB 1=BLE；未连接返回 -1
```

### 5.4 命令 / 请求

所有命令函数返回 `int`：**`1` = 命令已下发，`0` = 失败**（如未连接）。
命令的异步结果（成功/失败/状态）通过 `um_on_message` 回调上报。

```c
int um_set_dpi(const char* device_id, int level);       // 设置 DPI 档位
int um_meeting_create (const char* device_id);          // 创建会议
int um_meeting_destroy(const char* device_id);          // 结束会议
int um_meeting_pause  (const char* device_id);          // 暂停会议
int um_meeting_resume (const char* device_id);          // 恢复会议
```

## 六、事件协议（um_on_message 的 JSON）

所有离散事件统一为 `{"type":"...", ...}` 结构。**扩展性核心**：硬件未来升级只需新增 `type` 或字段，本协议结构保持稳定。

### 6.1 按键事件 `keyEvent`（核心）

SDK 只透传「哪个键 + 什么动作」，不做任何业务映射。

```json
{"type":"keyEvent","key":"<key>","action":"<action>","index":<N>}
```

| 字段 | 说明 |
|---|---|
| `key` | 物理键名：`speech` / `translation` / `m` / `ai` / `capture` |
| `action` | 动作：`down`（按下）/ `up`（抬起）/ `hold`（长按）/ `click`（单击） |
| `index` | **M 键专用**，第几个 M 键（从 1 起）；非 M 键为 0 或省略 |

**键 × 动作全集：**

| 键 (`key`) | 支持动作 (`action`) | 说明 |
|---|---|---|
| `speech` | `down` / `up` | 语音键 |
| `translation` | `down` / `up` | 翻译键 |
| `m` | `down` / `hold` / `up` | M 键，`index` 指示是第几个 M 键 |
| `ai` | `down` / `up` / `click` | AI 键 |
| `capture` | `click` | 截图键 |

**示例：**

```json
{"type":"keyEvent","key":"speech","action":"down"}
{"type":"keyEvent","key":"m","action":"hold","index":1}
{"type":"keyEvent","key":"ai","action":"click"}
```

> 业务逻辑示例：您的程序收到 `{"key":"speech","action":"down"}` 时开始录音，收到 `action:"up"` 时停止并送识别；收到 `{"key":"m","action":"hold","index":1}` 时触发第一个 M 键对应的功能（截图/语音打字/回车等，由您定义）。

### 6.2 设备信息 `deviceInfo`

随心跳/音频上报，包含设备序列号、电量、连接类型：

```json
{"type":"deviceInfo","sn":"000AEB20","battery":50,"deviceType":"usb"}
```

| 字段 | 说明 |
|---|---|
| `sn` | 设备序列号（十六进制字符串） |
| `battery` | 电量百分比（0–100） |
| `deviceType` | 连接类型：`"usb"` 或 `"ble"` |

### 6.3 DPI 变更 `dpiChanged`

设备 DPI 档位变化时上报（含调用 `um_set_dpi` 后的回执）：

```json
{"type":"dpiChanged","level":2}
```

### 6.4 会议状态

```json
{"type":"meetingCreated"}
{"type":"meetingDestroyed"}
```

> 未来若硬件新增事件类型，会以新的 `type` 值出现，已有的 `type` 和字段保持向后兼容。

## 七、音频数据（um_on_audio）

| 属性 | 值 |
|---|---|
| 编码 | 原始 PCM（无压缩头） |
| 采样率 | 16000 Hz（16 kHz） |
| 位深 | 16 bit（有符号小端） |
| 声道 | 单声道（mono） |
| 数据率 | 32 kB/s |

- 每次回调 `pcm` 指向一段音频数据，`len` 为字节数。
- **指针仅在回调期间有效**，需要落盘/送识别请立即拷贝。
- 验证方法：把数据顺序写入 `xxx.pcm`，用 Audacity「文件 → 导入 → 原始数据」，选择 `Signed 16-bit PCM / Little-endian / Mono / 16000 Hz` 即可播放。

## 八、各平台注意事项

### 8.1 Windows

- **运行期依赖**：您的程序目录（或 `PATH`）下必须能找到 `uMouseSdk.dll`、`avcodec-58.dll`、`avutil-56.dll`。最简单做法是把这三个 dll 与您的 `.exe` 放同一目录。
- **VC++ 运行库**：若运行报「找不到 VCRUNTIME140.dll」等，需安装 [Visual C++ Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe)（多数系统已自带）。
- **BLE 驱动**：蓝牙功能依赖系统自带 Bluetooth 协议栈（Windows 10/11 均已内置），无需额外驱动。
- **Windows 智能屏幕 / 杀毒软件**：首次加载 dll 可能被拦截，属正常现象，加入信任即可。

### 8.2 Linux（UOS / 麒麟 / 通用发行版）

**① USB 设备访问权限（重要）**

Linux 下 USB HID 设备节点（`/dev/hidraw*`）默认仅 root 可读写。**不安装权限规则时，只有 `sudo` 才能枚举到鼠标。** 正式部署不应要求 sudo，请一次性安装 udev 规则：

```bash
# 创建规则文件（按设备 VID/PID 匹配，默认 abc9:ca89）
echo 'KERNEL=="hidraw*", SUBSYSTEM=="hidraw", ATTRS{idVendor}=="abc9", ATTRS{idProduct}=="ca89", MODE="0666"' \
  | sudo tee /etc/udev/rules.d/70-umouse.rules

# 重载规则并触发
sudo udevadm control --reload-rules
sudo udevadm trigger

# 重新插拔鼠标后，普通用户即可直接访问
```

## 九、线程模型与最佳实践

### 线程约定

- **所有回调在 SDK 内部读线程触发**（非您的主线程）。
- 回调内**严禁**：
  - 长时间阻塞（如同步网络请求、文件大读写）——会拖慢音频/事件上报，导致丢帧；
  - 反向调用 `um_sdk_close()`——会死锁；
  - 持有重锁并与其他线程互等。

### 推荐模式：回调只拷贝，业务在工作线程处理

```c
/* 环形队列 / 线程安全队列（您的实现）*/
static Queue g_event_queue;

static void on_message(const char* id, const char* json) {
    /* 回调线程：只做拷贝并入队，立即返回 */
    enqueue(&g_event_queue, strdup(json));
}

/* 工作线程：出队后做耗时业务处理 */
void* worker_thread(void*) {
    char* json;
    while ((json = dequeue(&g_event_queue)) != NULL) {
        handle_business(json);   /* 这里可以慢 */
        free(json);
    }
    return NULL;
}
```

### 内存与生命周期

| 数据 | 有效性 | 处理建议 |
|---|---|---|
| `device_id`（回调参数） | 仅回调期间 | 需留存立即 `strdup` |
| `json`（on_message） | 仅回调期间 | 需留存立即 `strdup` |
| `pcm`（on_audio） | 仅回调期间 | 需留存立即 `memcpy` |
| `um_sdk_version()` 返回值 | 整个生命周期 | 静态字符串，可直接保存指针 |

### 退出流程

```c
um_sdk_close();   // 幂等，停止线程、释放资源
// close 之后不再有任何回调触发，可安全退出
```

## 十、常见问题（FAQ）

**Q1：程序运行后没有触发 `on_connected`，`um_get_device_count()` 一直是 0。**
- 检查设备是否已通过 USB 线连接或蓝牙配对；
- Linux：检查 USB 权限规则是否已安装（见 8.2），未装规则时需 `sudo` 运行；
- Windows：检查设备管理器中设备是否正常识别；
- 用 `um_sdk_init(1)` 打开日志查看内部探测过程。

**Q2：能收到 `on_connected` 但收不到音频。**
- 确认已注册 `um_register_audio` 回调；
- 部分设备需先触发一次按键（如语音键）才开始推送音频流；
- 检查电量，低电量可能暂停音频。

**Q3：C# / Python 集成后程序闪退或报「访问非法内存」。**
- 几乎都是**回调委托被垃圾回收**导致。请把回调对象存为长期存活（字段/模块级变量），不要用临时变量注册。详见 4.2 / 4.3。

**Q4：能否同时连接多个设备？**
- 首版为单设备模型（`um_get_device_count()` 返回 0 或 1），`device_id` 已作为参数预留，未来扩展多设备时对外 API 签名不变。

**Q5：SDK 内置了 FFmpeg，我的商业软件许可是否有问题？**
- FFmpeg 以 **LGPLv2.1** 动态链接（.dll/.so/.dylib 形式）分发，满足 LGPL 的「可替换」义务即可商用。**请务必保持 FFmpeg 为动态链接，不要静态化**，并随包分发 `COPYING.LGPLv2.1`。详见随包许可证文件。

**Q6：M 键按下后 SDK 会自动触发截图/语音吗？**
- 不会。SDK 只透传 `{"type":"keyEvent","key":"m","action":"down","index":1}`，做什么完全由您决定。这是为了让您能自定义每个按键的业务含义。

**Q7：不同国产化 Linux（UOS vs 麒麟）的包能互换吗？**
- 不建议。虽然都是 Linux/glibc，但系统库（FFmpeg、systemd/udev、dbus）版本可能不同，互换可能导致动态库加载失败。请按目标系统选用对应包。

**Q8：如何确认 SDK 是否正常加载？**
- 调用 `um_sdk_version()` 应返回 `"0.1.0"`；返回 NULL 或崩溃说明动态库未正确加载（检查路径 / 运行期依赖）。

## 十一、版本与许可

### 版本

- 当前 SDK 版本：**0.1.0**（可通过 `um_sdk_version()` 在运行时查询）
- 升级 SDK 时，对外 C ABI 保持向后兼容，新增能力以 JSON `type` 或新增导出函数形式提供。

### 第三方组件与许可

本 SDK 包含以下第三方组件，相关许可证原文随包分发：

| 组件 | 用途 | 许可证 | 随包文件 |
|---|---|---|---|
| FFmpeg (libavcodec/libavutil) | SBC / ADPCM 音频解码 | LGPLv2.1（动态链接） | `COPYING.LGPLv2.1` |
| hidapi | USB HID 跨平台访问 | BSD-3-Clause | `LICENSE.hidapi-bsd` |

- FFmpeg 遵循 LGPL，以**动态库**形式分发以满足「用户可替换」义务，**集成方请勿将其改为静态链接**。
- 完整第三方许可声明见随包 `THIRD_PARTY_LICENSES.txt`。

### 鼠标硬件私有协议

设备使用的通信协议为厂商私有，本 SDK 已获得对外授权。集成方不得反向私有协议用于其他用途。

## 附录 A：完整 C 示例（含音频落盘）

```c
/*
 * 完整示例：注册全部回调 → 初始化 → 运行到回车 → 落盘 PCM → 退出。
 * 编译：见「四、集成到您的工程 / 4.1」。
 */
#include "umouse_sdk.h"
#include <stdio.h>
#include <string.h>

static FILE* g_pcm = NULL;
static long  g_pcm_bytes = 0;

static void on_connected(const char* id, int mode) {
    printf("[连接] %s via %s\n", id, mode == UM_CONN_BLE ? "BLE" : "USB");
}
static void on_disconnected(const char* id, int mode) {
    printf("[断开] %s via %s\n", id, mode == UM_CONN_BLE ? "BLE" : "USB");
}
static void on_message(const char* id, const char* json) {
    printf("[事件] %s %s\n", id, json);
}
static void on_audio(const char* id, const uint8_t* pcm, int len) {
    (void)id;
    if (g_pcm && pcm && len > 0) {
        fwrite(pcm, 1, (size_t)len, g_pcm);   /* 立即落盘 */
        g_pcm_bytes += len;
    }
}

int main(void) {
    printf("声云智能鼠标 SDK demo, version %s\n", um_sdk_version());

    g_pcm = fopen("out.pcm", "wb");

    um_register_connected(on_connected);
    um_register_disconnected(on_disconnected);
    um_register_message(on_message);
    um_register_audio(on_audio);

    um_sdk_init(1);   /* debug=1 开日志 */

    printf("运行中... 按回车结束。\n");
    getchar();

    um_sdk_close();

    if (g_pcm) {
        fclose(g_pcm);
        printf("PCM 已写入 out.pcm，共 %ld 字节。\n", g_pcm_bytes);
        printf("用 Audacity 导入：Signed 16-bit PCM / Little-endian / Mono / 16000 Hz。\n");
    }
    return 0;
}
```
